## What maintainers do

- **Review pull requests.** The maintainer is the code owner of every path in
  [`.github/CODEOWNERS`](.github/CODEOWNERS) and reviews every change. Changes to a skill's
  credential handling, its sandbox definition, or the security policy get particular attention.
- **Handle security reports.** Vulnerabilities are reported privately — see
  [`SECURITY.md`](SECURITY.md). Never in a public issue.
- **Triage issues** and keep the published skills working against the current XORCISE engine.

## Contacting a maintainer

| Reason | Where |
| --- | --- |
| Bug or feature request | [Issues](https://github.com/xorcise-ai/xorcise-skills/issues) — use the templates |
| Usage question | [Discussions](https://github.com/xorcise-ai/xorcise-skills/discussions) |
| **Security vulnerability** | **Private advisory** — see [`SECURITY.md`](SECURITY.md) |
| Something in the XORCISE engine | [xorcise-ai/xorcise](https://github.com/xorcise-ai/xorcise/issues) |
| Code of Conduct concern | guru@xorcise.ai |

Please use the public channels for anything that is not sensitive — an answer in the open
helps the next person with the same question.

## Becoming a maintainer

Maintainership is offered, not applied for, and follows a track record of good contributions
and sound judgement — particularly around credential handling and run isolation, where a
careless change does real damage.

If you would like to move in that direction, the path is ordinary: pick up issues, review
other people's pull requests, and help with triage. See [`CONTRIBUTING.md`](CONTRIBUTING.md).
